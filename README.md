## Requirements

This project is developed and tested with Python 3.12.

## API key configuration

Before running MetaDesigner, users need to configure the required API keys in a `.env` file.

## How to run

The design objective is specified in main.py.

To define a new metasurface design task, open main.py and modify the value of USER_QUERY:

USER_QUERY = "Describe the metasurface design objective here."

For example:

USER_QUERY = "Design an RGB metalens that focuses red, green and blue light to three different positions on the same focal plane."

Then run:

python main.py

MetaDesigner will parse the natural-language objective and autonomously execute the corresponding design workflow.

## Outputs

During execution, MetaDesigner may generate:

executable Python code;
simulation or optimization results;
metasurface design files;
intermediate data files;
Markdown-format technical reports.

Generated files are saved in the working directory or in the file-management paths defined by the project.

## Reasoning trajectories for manuscript examples

The reasoning trajectories of the three examples reported in the manuscript are provided in the following files:

RGB metalens design: Focus/GeneratedFiles/Reasoning Trajectory.md

Optical generative modeling: Generator/GeneratedFiles/Reasoning Trajectory.md

Multi-plane holography: Holography/GeneratedFiles/Reasoning Trajectory.md

These files record the step-by-step reasoning process, tool calls and intermediate outputs generated by MetaDesigner during each task. They can be used to inspect how the agentic system plans, executes, verifies and corrects the design workflow.

## Notes on base models

In the current implementation, DeepSeek is used as one of the base models for long-horizon reasoning. However, its performance may be unstable across different tasks, prompts or API conditions. Users with access to stronger or more stable models may replace DeepSeek with other base models.

When changing the base model, please ensure that:

the model supports sufficiently long context;

the model can follow tool-use instructions reliably;

the API interface is compatible with the agent framework;

the required API keys are correctly configured in the .env file.

## Reproducibility

To reproduce or redesign a task, configure the required API keys, modify USER_QUERY in main.py, and run:

python main.py

Because LLM-based agents may show stochastic behavior, repeated runs can produce different reasoning trajectories, generated code or optimization results. For the final quantitative performance values reported in the manuscript, please refer to the manuscript and the corresponding source data.

## Memory management

MetaDesigner maintains a persistent memory across runs. Information generated during previous executions may be stored and reused in subsequent tasks.

If you would like to start from a clean state and prevent the agent from being influenced by previous runs, you can clear the stored memory by running:

python showMemory.py

The script provides options for inspecting and deleting the stored memory.

## Terminology

In the manuscript, the agent responsible for generating custom tool code is referred to as the Programmer.

In the released codebase, the same agent is named Coder.

The two terms refer to the same component and are functionally equivalent.
